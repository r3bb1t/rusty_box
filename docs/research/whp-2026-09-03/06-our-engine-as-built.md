## 2. The time model, precisely

### (a) `BxPcSystemC` — `rusty_box/src/pc_system.rs`
- One clock: `ips: u64` set by `initialize(ips: u32)` (:635-651), read by `ips()` (:655-657); `rate() -> ClockHz` (:667-669, falls back to `ClockHz::BOCHS_DEFAULT` on zero); `clock_at(now_ticks) -> VmClock` (:677-679) is "the single place the two are married".
- `time_ticks() = ticks_total + (curr_countdown_period - curr_countdown)` (:868-870). `time_usec() = ticks*1e6/ips` (:874-893), `time_nsec()` (:896-899), `usec_to_ticks()` floor (:881-885).
- Countdown: `tickn(n)` decrements `curr_countdown`, calling `countdown_event()` each time it reaches 0 (:692-702); `tick1` (:707-712). `countdown_event` (:718-786) adds the period to `ticks_total`, scans every timer (`>=`, not Bochs `==`, :730-736), deactivates one-shots, advances continuous ones by `period` until past `ticks_total` (:743-748), computes the next period clamped to `[1, 0xFFFF_FFFF]` (:766-772), records fired owners (:776-786).
- Registration: `register_timer(owner: TimerOwner, period_TICKS, continuous, active, id)` (:1017-1058; Bochs `register_timer_ticks`); `register_timer_usec` converts via `usec_to_ticks` (:1064-1078; Bochs `register_timer`, pc_system.cc:254-260 uses `useconds * m_ips`).
- Arming: `activate_timer_at_ticks(idx, deadline_abs, continuous)` (:1086-1108 — a due/past deadline becomes `now + 1`, :1097-1102; `shorten_countdown_to` :998-1011); `activate_timer_at_ticks_with_period` (:1114-1124); `activate_timer(idx, period_ticks, continuous)` (:1130-1141); `activate_timer_usec` (:1147-1161, `0` reuses the stored period); `activate_timer_nsec` (:1167-1183); `reactivate_timer_relative` (:1189-1202); `deactivate_timer` (:1219); `unregister_timer` (:1229). `Timer{flags IN_USE|ACTIVE|CONTINUOUS, period, time_to_fire (absolute tick), owner, id}` (:133ff). `NULL_TIMER_INTERVAL = 0xFFFF_FFFF` (:83), `MIN_ALLOWABLE_TIMER_PERIOD = 1` (:88), `BX_MAX_TIMERS = BX_MAX_SMP_THREADS_SUPPORTED + 21` (:73-77), `TimerOwner` has 17 variants (:91-131).
- Queries: `get_num_cpu_ticks_left_next_event() = curr_countdown` (:1249-1251), `countdown_would_expire_after` (:1258-1260), `next_timer_deadline_at` (:1316-1330, O(n)), `ticks_to_next_timer_deadline` (:1337-1341), `has_fired_timers`/`take_fired_timers` (:1363-1379). `isa_bus_delay` ticks `ips*2/1e6` (:1350-1356).
- `VmClock{now: VmInstant, rate: ClockHz}` — `rusty_box_core/src/time.rs:244-309`: `micros()`, `nanos()`, `micros_phase()` (PIT carry), `after(span)`, `after_micros` (ceil, never same tick), `after_micros_floor`, `after_nanos_floor` (HPET). `HostClock` trait + `ManualClock` exist (time.rs:345-378) but have **1** consumer outside core (grep `HostClock|ManualClock` over rusty_box/src, rusty_box_devices/src, rusty_box_whp_engine/src, rusty_box_gui/src: 1 hit).
- What a device receives: `DeviceCtx{clock: VmClock, irq: &mut dyn IrqSink, timers: &mut dyn TimerService}` (`rusty_box_devices/src/api.rs:284-305`); built by `with_device_ctx(irq, pc_system, handles, now_ticks, f)` → `pc_system.clock_at(now_ticks)` (iodev/wiring.rs:24-43). `WheelTimerService` arms at `now_ticks + delay` (wiring.rs:157-208; usec→ticks `div_ceil(..).max(1)` :154-160) via `activate_timer_at_ticks_with_period`. `TimerService{arm_oneshot_usec, arm_periodic_usec, arm_oneshot_ticks, cancel}` (api.rs:267-288); `TimedDevice::timer_fired(local, fires, ctx)` (api.rs:405-412). Unconverted owners use `BxDevicesC::request_timer_after_usec[_with_mode]` → `TimerRequest::Activate{deadline_ticks, period_ticks, continuous}` (iodev/mod.rs:528-560), drained by `drain_device_timer_requests` for 12 owners (timers.rs:672-780).
- **Which "now" a device sees**: interpreter port I/O passes `self.system_ticks()` (cpu/io.rs:1603-1606) → live; the WHP raw port exit passes `io.pc_system.time_ticks()` (engine.rs:2786) → **the wheel, which does not move during a slice** (engine.rs:1889-1896 says so in its own words). MMIO reached through the shadow uses `ExecCtx::system_ticks()` = `LiveUp{wheel + (cpu_ticks - cpu_ticks_at_sync)}` (proc_ctrl.rs:317-331) → wheel plus shadow-retired instructions.

### (b) CPU ticks and the LAPIC timer
- `cpu_ticks() = icount + tick_surplus` (cpu.rs:996-998); `mark_tick_sync` (:1001-1003); `tick_delta_since_sync` (:1006-1008). `SliceClock{Detached, LiveUp{cpu_ticks_at_sync}, FrozenRound{epoch}}` (cpu.rs:338-350), set once per slice by `begin_slice_clock` (cpu.rs:1833-1845) from `cpu_loop_n_slice`/`cpu_run_trace_slice` (:2106, :2128).
- LAPIC fields (apic.rs:418-442): `timer_initial/current`, `ticks_initial`, `current_ticks`, `ticks_at_sync`, `cpu_ticks_at_sync`, `timer_divide_factor`, `tsc_deadline_supported`, `timer_active`. `live_ticks(cpu_ticks)` (:604-615) = `ticks_at_sync + (cpu_ticks - cpu_ticks_at_sync)` on UP, frozen `current_ticks` on SMP.
- Programming: `set_initial_timer_count(value, current_ticks)` (:1905-1957) → `timer_activate_request = at_ticks(current_ticks + value*divide, true)` — **one LAPIC timer tick = one machine tick / divide, i.e. the LAPIC bus clock IS `ips`**, exactly Bochs apic.cc:1062-1064/1111-1112 (`activate_timer_ticks(timer_handle, Bit64u(timer_initial)*timer_divide_factor, 0)`, `ticksInitial = bx_pc_system.time_ticks()`). `set_divide_configuration` (:1896-1903). `periodic(current_ticks)` (:1841-1893) fires `trigger_irq` and re-arms (mode 1) or requests deactivate (one-shot). `get_current_timer_count` (:1960-1981); MMIO 0x390 read uses `live_ticks(cpu_ticks)` (:935-956; access.rs:247/295 pass `self.cpu_ticks()`).

- Wheel side: `service_lapic_timer_requests` (scheduler.rs:822-850) stamps the epoch and calls `apply_lapic_timer_request` (:775-820) → `pc_system.activate_timer_at_ticks(handle, deadline, false)` — always one-shot on the wheel. Under WHP the vector then waits for the next `stage_injection` (slice head :1337 or exit tail :2181).

### (c) The TSC
- Interpreter: `TSC_SCALE = 1`; `get_tsc(system_ticks) = system_ticks + tsc_adjust`; `set_tsc(newval, system_ticks)` sets `tsc_adjust = newval - system_ticks` (proc_ctrl.rs:266-290); `RDTSC` → `get_virtual_tsc(self.system_ticks())` (:922-946); `RDMSR TSC` same (:1058). Bochs `get_TSC` = `bx_pc_system.time_ticks()` (comment :268).
- WHP: `TRAPPED_MSRS = MsrExits{tsc_read: false, tsc_write: false, ..ALL}` (engine.rs:114-118); RDTSC exit is not requested (`extended_vm_exits{cpuid, msr, exception}` :891-899) and `ExitReason::Rdtsc => Err(unserviced)` (:2119). `MSR_REGS` lists `Reg::Tsc` LAST (state.rs:65-79); `IMPORTED_MSRS = MSR_VALUES - 1` (:105); `import` skips `WORD_VALUES + TSC_SLOT` (state.rs:281-285). The bridge at read-back, engine.rs:1770-1786: "the shadow is set to the counter the guest last saw, at the tick the machine is standing on. Rebased at every read-back" → `cpu.set_tsc(state.msrs.tsc, machine_ticks)` with `machine_ticks = io.pc_system.time_ticks()` at :1369/:2522/:2668/:2692.
- Consequence: on hardware the TSC runs at the host rate from the host epoch (divergence H2, docs/bochs-parity-divergences.md:352-390); on the shadow it is `wheel + tsc_adjust` and advances one per shadow instruction; between read-backs the two drift by `(host_hz - ips*32) * wall`.

### (d) Device clocks and the "two clocks" hazard, enumerated
- HPET: `HPET_CLK_PERIOD = 10` ns → 100 MHz (hpet.rs:31); `time_nsec()` = `self.clock.nanos()` (:281-283); `set_now(clock)` stamped by the caller (:221); comparator → `HpetTimerOp::ArmAtTicks(clock.after_nanos_floor(..))` (:397) → `activate_timer_at_ticks` (timers.rs:657-663). `HPET_NUM_TIMERS = 3` (hpet.rs:28).
- ACPI PM timer: `PM_FREQ = 3_579_545` (acpi.rs:30); `live_time_usec(icount)` = `time_usec + (icount - icount_at_sync)*1e6/ips` (:795-807) or `Instant::elapsed()` when `enable_realtime_sync` (:787-790) — enabled only under `config.sync_realtime` (mod.rs:1500-1504, default off). Overflow timer one-shot at the next 24-bit wrap (:855-872, :907-915).
- PIT: 1,193,181 Hz (pit.rs:37); `sync_to_icount(clock)` uses `clock.micros_phase()` (:1108-1135) or the realtime path (:1109-1114, same gate).
- RTC: periodic `976 us` at the default rate nibble (cmos.rs:510-511, 616-618) only while `REG_B.PIE` (:626-633); one-second `1_000_000 us` (:291); UIP `244 us` one-shot (:290).
- VGA: 0x3DA retrace bits from `current_usec(clock) - display_start_usec` mod `vtotal_usec` (vga.rs:1627-1640); `vtotal_usec` default 14,268 us ≈ 70 Hz (vga.rs:1238, 1457-1469).

**Idle Alpine, shortest recurring deadline (ips = 300 M, computed from the table):**
- 8042 continuous: 150 us = 45,000 ticks → this caps every UP batch (scheduler.rs:204-208) and therefore every WHP slice budget at ≤45,000 ticks. `host_time_exactly(45_000)` = 45,000 / (3e8 × 32) s = **4.7 us** of host time, just above the 3 us hardware floor; any timer nearer in phase pushes it under. The handoff measured a mean budget of 18,587 ticks = 1.9 us host (docs/whp-alpine-handoff.md:151-153), the memory note 86% zero-exit slices (`whp-throughput-ceiling-measured.md`).
- LAPIC one-shot: busy 1 kHz = 300,000 ticks (31 us host); idle ~30 Hz = 10 M ticks (1 ms host). VGA vertical 14,268 us = 4.28 M ticks. CMOS one-second 3e8 ticks. PIT: shut down by a LAPIC-clockevent kernel, else 1 kHz/18.2 Hz. HPET: only if the guest picks it as clocksource/clockevent (then 3 comparators, one-shot).
- So the 8042's 150 us is the ONLY sub-millisecond always-on recurring deadline; without it the idle-guest slice would be bounded by the LAPIC timer (1 ms busy / ~33 ms idle) and the VGA retrace (14 ms).

**Under a host-time device clock:** the 8042 delay is a real-time serial delay — it becomes a 150 us **one-shot** armed only by `activate_timer()` (keyboard.rs:1439-1445, called from the six enqueue/port paths at :753, :778, :1184, :1213, :1884, :1896) and by the `irq1/irq12_requested` latches (which Bochs raises only from this handler); no continuous cap. PIT/RTC/VGA/one-second/ACPI/HPET periods are already real-time quantities and would be re-expressed in host time unchanged in value; the `Slowdown` timer vanishes (host time IS the clock); the LAPIC timer stays a machine-tick quantity unless the LAPIC moves to the hypervisor (§6); the BM-DMA 1 us poll and the seek/serial one-shots are the same one-shots on host time.

## 4. The shadow/state seam cost model (`rusty_box_whp_engine/src/`)

**What one exchange carries** (`state.rs`): `WORD_REGS` = 29 words (16 GPRs, RIP, RFLAGS, CR0/2/3/4/8, DR0-3/6/7; :28-59), `MSR_REGS` = 13 (EFER, APIC_BASE, STAR, LSTAR, CSTAR, SFMASK, KERNEL_GS_BASE, SYSENTER×3, PAT, XCR0, TSC last; :65-79), 8 segments (:114-124), 2 tables (:129) → `WHOLE_STATE = 52` (:177). `export` = ONE `read_registers` of 52 (:322-326); `import` = ONE `write_registers` of 51 (TSC skipped by index, :281-302). Plus the XSAVE area: `read_xsave` of the compacted area (872 bytes on this host per docs/whp-alpine-handoff.md:25-31; capacity 4096, xsave.rs:249) at every read-back (engine.rs:1729); `write_xsave` only when `vector_file_differs` (fpu/vector/opmask/mxcsr, xsave.rs:229-232; engine.rs:1673-1676) or no `held`. `InterruptState`: 1-word read per read-back (:1738-1744), written only when changed (:1667-1672). `VcpuArchState` shape: arch_state.rs:324-358 (`vector: [[u8;64]; VECTOR_REGISTERS]` — the clone in `*held = Some(state.clone())` copies the whole vector file, :1733/:1616/:1732).

**`discard_decoded_traces` cost:** arch_state.rs:471-474 → `BxICache::flush_all` (icache.rs:349-368): a **linear walk over `BX_ICACHE_ENTRIES = 64 * 1024` entries** (icache.rs:74) of 24 bytes each (`size_of::<BxICacheEntry>() == 24`, icache.rs:100) = **1.5 MiB written** per read-back, plus the page-split index, `bump_link_timestamp`, `mpindex = 0`. The engine's own doc quotes it as "a 52-register exchange and a 1.5 MiB decoded-trace flush" (engine.rs:530). It runs on EVERY read-back, i.e. every `finish_on_the_shadow`/`burst` and every slice end whose hardware ran (:1367-1370).

**The held-skip:** `install_the_shadow` compares the exported shadow against `held` with the TSC swapped to the previous value ("comparing it asks whether a register that is never sent has changed, which it always has", :1598-1612) and returns without writing when equal. `ran_since_read_back` (`Started` :540-553) is set the moment `partition.run` returns (:1920) and cleared only at the tail of `read_back_into_the_shadow` (:1791); a slice that ends without the hardware having run since the last read-back skips the exchange and counts `read_backs_skipped` (:1367-1376). Measured (memory note `whp-throughput-ceiling-measured`): 353,784 skips against 353,705 memory exits on Alpine; DLX unchanged because its exits are ports and cancels.

**`Started`** (engine.rs:475-565): `alarm` (declared before `partition` — drop order is load-bearing, :469-474), `partition`, `state: VcpuArchState` (reused), `installed: MemoryPlan`, `shadowed: bool` (:487-508), `held_interrupt_state: InterruptStateWord` (:509-523), `held: Option<VcpuArchState>` (:524-534), `ran_since_read_back` (:535-553), `consecutive_mmio: u32` (:554-560), `xsave: XsaveArea` (:561-566), `inject: InjectState` (:567-571). `InjectState{in_flight, if_flag, cr8, shadowed, window}` (:344-370) refreshed from every exit header (`refresh_from`, :385-395: bit 6, bit 12, RFLAGS.IF, Cr8) or from the shadow after an errand (:435-438). `InterruptStateWord{shadow, nmi_masked}` (:446-471).

**The alarm** (`alarm.rs`): one thread per engine life (:106-120, `"whp slice alarm"`); `arm(deadline)`/`disarm()` are a mutex write + generation bump + `notify_one` (:123-149); `watch` (:165-229) sleeps on `wait_timeout` for everything beyond **`SPIN_MARGIN = 2 ms`** (:58) and spins the last 2 ms on a generation counter (:198-206), then `canceller.cancel()` (:220-223). Measured in its own doc: "asked for 50 microseconds it returns after 15,467 on average — 309 times the request" (:42-49). Every hardware slice (≤45,000 ticks ≈ 4.7 us host) is therefore spun whole: **a core is busy for as long as the guest is on the hardware** (:53-56).

## 6. The IRQ fabric

**Where it lives:** `IrqFabric` is `rusty_box/src/iodev/irq.rs:61-244` (not under emulator/): owns `pic: BxPicC`, `ioapic: BxIoApic`, `acknowledge_count`, `vectors_acknowledged[256]`. LAPICs are NOT in the fabric — each lives on its CPU (`cpu.lapic: BxLocalApic`, apic.rs) — which is why the IOAPIC→LAPIC hop is machine work in the scheduler.

**Device → controllers (synchronous, inside the access):** `set_isa_level(line, level)` → `pic.set_irq_level`; if the 8259 reports `IoApicEdge::Crossed` the same call drives `set_ioapic_pin(line, level)` (irq.rs:121-127) → `ioapic.set_pin_level` → `service_ioapic()` (:148-153, :179-191) → `ioapic.service(&mut PicAcknowledge{..})` (ioapic.rs:786), which resolves ExtINT vectors through the SAME counted INTA (`acknowledge_8259`, irq.rs:250-281) and **enqueues** `PendingIoApicDelivery{vector, dest, dest_mode, delivery_mode, trigger_mode}` (ioapic.rs:852ff). Devices reach the fabric as `IrqSink` (irq.rs:283-293; api.rs `IrqSink::set_level/raise/lower`). HPET pins ≥16 drive the IOAPIC only (timers.rs:585-606).

**Controllers → CPU (deferred to a scheduler boundary):** `sync_final_event_levels` (scheduler.rs:1220-1288): PIC INT pin → cpu0 `BX_EVENT_PENDING_INTR` (:1224-1231); `ioapic.take_pending_deliveries()` → `deliver_ioapic_to_lapics(delivery)` (:1238-1258 → :714-773: lowest-priority arbitration for delivery mode 1, focus processor for non-xAPIC, physical/logical destination via `ioapic_targets_cpu` :687-699) → `deliver_lapic_bus_interrupt` (:574-597) → `lapic.deliver`/`trigger_irq` (apic.rs:1535, :1580-1614: IRR/TMR bits, `service_local_apic`) → `intr` → `BX_EVENT_PENDING_LAPIC_INTR` (:1268-1275). Mid-slice, the per-exit drain is `PcIo::sync_io_events` (io.rs:101-131) — it moves only the latched 8259 level, HRQ and the boundary request; an IOAPIC delivery queued mid-slice waits for `service_scheduler_boundary` (its presence is in the boundary predicate, scheduler.rs:952-955). **This IOAPIC → LAPIC hop is the "one coupling a hypervisor changes"**: it is the only place a device interrupt is written into a LAPIC's IRR, and under a hypervisor-owned LAPIC it becomes `WHvRequestInterrupt`.

**CPU INTA:** `acknowledge_external_interrupt` (cpu/event.rs:661-732): LAPIC first (`lapic.intr` → `acknowledge_int()` → `sync_lapic_events`, spurious vector included, :663-681), then the 8259 (`irq.int_pin_asserted()` → `irq.acknowledge()` :684-692), else reconcile the stale pin and clear `BX_EVENT_PENDING_INTR` (:693-729). `has_deliverable_ext_int()` = `pending_event & DeliverableInterrupt::MASK != 0 || lapic.intr` (arch_state.rs:581-583, IF-blind by design); `has_non_ext_int_event()` (:588-590); `set_lapic_tpr_from_cr8` (:597-599). The WHP engine's `pop_deliverable_vector` (io.rs:168-178) IS this body, so the acknowledge order and counters are shared; the machine-side alternative (`iac()` scheduler.rs:536-538 → `device_manager.iac()`) runs only under `EventDelivery::Machine` (run.rs:783-797).

**EOI:** LAPIC `receive_eoi` (apic.rs:1428-1449) clears ISR and, for a TMR (level) vector, sets `pending_eoi_vector`; `service_lapic_local_events` drains it at the boundary → `irq.receive_eoi(vector)` (scheduler.rs:902-910) → `ioapic.receive_eoi` clears remote-IRR and re-services (ioapic.rs:752-770). Under WHP an EOI is an MMIO write to `0xFEE000B0` → memory exit → `finish_on_the_shadow` → `lapic.write` (access.rs:300) → `pending_eoi_vector`; the IOAPIC learns of it at the next boundary.

**LAPIC MMIO carve-out:** `LOCAL_APIC_REGION = 0xFEE0_0000..0xFEF0_0000` (memory/plan.rs:45) is excluded from every direct window (`carve_outs.add(..)`, plan.rs:115), so every LAPIC register access exits (`nested_page_fault`) and is finished on the shadow — 353,705 memory exits over an Alpine run (memory note), one read-back + impose each. The IOAPIC window is a registered MMIO region answered by the fabric (`mmio_read/mmio_write`, irq.rs:164-177), carved the same way.

**MSI:** none. `grep -in msi` over iodev/pci.rs, iodev/devices.rs, iodev/irq.rs, rusty_box_devices/src/pci.rs hits only `ramsize`. The HPET FSB route writes guest memory directly and is never advertised (timers.rs:607-650).

**Binding surface already present** (`rusty_box_whp/src/partition.rs`): `LocalApicMode::{None, XApic, X2Apic}` (:39-47) set by `PartitionConfig::local_apic` (:260); `Partition::request_interrupt(InterruptRequest)` (:812-813) and a partition-scoped `InterruptRequester` for other threads (:581, :931-947); `inject(PendingInterruption)` (:800); `cancel_run`/`canceller` (:642, :570); `internal_activity`/`set_internal_activity` (:820-831 — unwritable per the probe). The probe measured: under `None`, `WHvRequestInterrupt` is refused `ERROR_HV_OPERATION_DENIED`; under `XApic`, a halted VP never leaves `WHvRunVirtualProcessor`, a Fixed request mid-run did not run (APIC not software-enabled by the real-mode probe guest), an NMI request did (docs/whp-platform-probe-2026-08-27.md:140-166).

## 7. The existing design docs' claims, checked against code

The REPLAN v4 document itself is NOT in the repository (grep `REPLAN` over docs/ finds only citations: safety-doctrine.md:195, plans/2026-08-29-whp-fast-path.md:1263, specs/2026-08-22-display-seam-design.md:3, specs/2026-08-22-mmio-windows-design.md:6-9, specs/2026-08-29-…:6-7,341-408, whp-platform-probe-2026-08-27.md:32,54,83,100,116,182). It lives in `~/.claude/plans/currently-we-have-tightly-swirling-crayon.md` with a pointer note `~/.claude/projects/…/memory/replan-v4-hypervisor.md`; the decision texts below are quoted from that note and from the in-tree citations of them.

**Decisions a continuous-vCPU + host-time-devices + hypervisor-LAPIC design would REVERSE:**

1. **REPLAN v4 decision 1 — one tick clock on both engines, rate == ips under WHP.** Note: "Time = tick clock with a stated RATE on both engines (`VmClock{now, rate}`), rate == ips under WHP too (host ns → ticks, u128 remainder). Every conversion a NAMED core fn preserving its rounding … v3 wire format UNCHANGED, no version bump." In tree: `ticks_elapsed` doc — "Both engines denominate time in ticks at `ips`, so a device deadline armed under one is the same deadline under the other and a snapshot crosses between them unchanged (REPLAN decision 1)" (engine.rs:2977-2981). Host-time devices break "same deadline under either engine" and the unchanged v3 timer wire format (pc_system.rs:1455-1461).
2. **REPLAN v4 decision 6 — `LocalApicEmulationMode::None`, our own `cpu/apic.rs`, injection ours end to end; XApic stage DROPPED (amended 2026-08-27).** In tree: "No APIC in the partition: this port's own `cpu/apic.rs` is the guest's local APIC, its 8259 pair stays in host memory, and injection is therefore ours end to end. Measured (probe finding 10): under `XApic` a halted processor never leaves `WHvRunVirtualProcessor`, which would strand the timer wheel on a thread that never returns" (engine.rs:876-882); "The partition was created with no local APIC of its own precisely so that delivery stays on this side (REPLAN decision 6)" (:1214-1218). The justification is exactly the single-thread constraint the new design removes.
3. **REPLAN v4 decision 9 — one thread, "exactly two cross-thread pokes" (stop flag, waker); "Machine holds ZERO locks".** Note: "decision 9 — its 'exactly two cross-thread pokes' survives only because stage 1 was dropped; `XApic` would have needed a third." Probe: "`XApic` … forces a second thread — either one that owns the devices and delivers through `WHvRequestInterrupt`, or one that periodically cancels the run … Stage 1 is viable, but it buys a threading model that REPLAN decision 9 spent effort avoiding" (probe:168-182; table :195-197 "Three under `XApic`: stop flag, waker, and interrupt delivery"). The new design is precisely that threading model.
4. **REPLAN v4 decision 5 (amended) — the shadow `BxCpuC` is MANDATORY.** Probe finding 2: "a trapped memory exit gives `InstructionLength = 0` and does not advance RIP, and for a read-only window carries no instruction bytes" (probe:40-58; note "decision 5 — shadow CPU promoted to mandatory"). Not reversed for MMIO/CPUID/MSR, but a hypervisor LAPIC removes the largest MMIO exit class (the 0xFEE00000 page) and the 8042/PIT/RTC port exits stay; the shadow's role shrinks from "every exit" to "MMIO/CPUID/MSR/exception".
5. **Injection spec (2026-09-01) "Rejected approaches" #1 — partition-local APIC.** Quoted: "**Partition-local APIC** (`LocalApicMode::XApic`): H0 measured that a halted processor under XApic never returns from the run call (probe finding 10), stranding the timer wheel; and LAPIC state would live in two places, which engine switching and snapshots cannot tolerate" (spec:26-30). Both halves are the design's own costs: the wheel moves to a thread, and SEC_LAPIC must be read from the partition (§6 table).
6. **Fast-path spec (2026-08-29) §6 "Cross-engine snapshot restore — given up on the fast path — tick and host-time clocks differ"** (spec:292-304) — a consequence the new design accepts or must solve.
7. **Divergence registry entries whose premise changes:** H2 "The time-stamp counter is the host's … Price of closing it: a cross-engine TSC bridge" (docs/bochs-parity-divergences.md:352-390) — host time makes the host TSC the design, not a divergence; D1 "A halted machine's virtual time is advanced by the scheduler, not by an in-CPU spin" (:18-42) — moot when device time is host time; D3 "A fast REP string burst stops at the next timer deadline" (:144-176) — moot on hardware.
8. **The `SliceEngine` contract itself:** `PROGRESS_UNIT`, `EVENT_DELIVERY`, `SliceRequest{instructions, strict, …}` and "the machine decides which processor runs and for how long" (mod.rs:626-633; engine.rs:1-21) — a continuous vCPU has no slice request to honour.

**Decisions the new design AGREES with (not reversed):**
- Fast-path spec §2 decision 1: "On the fast path, guest time equals host time. Device timers move to a host clock, off the run thread. The closed loop (guest clock → ticks → run time → next device deadline → slice length) is what forces microsecond slices, and it goes" (spec:87-90) — this IS the proposed direction; decision 5 "The timing model is a policy, not a constant" (:99-102) and §10 Q3 "Where the timing policy is declared — on the engine, the machine, or the profile" (:422) remain to be decided; decision 7 "`no_std`/`no_alloc` is load-bearing … interpreter-only" (:105-108) is preserved because the WHP engine crate is std-only (§5); §9 "`MachineRunner` must stay optional … wasm and UEFI call `step()` directly" (:404-408).
- REPLAN decision 12 (emulator never depends on a backend; rusty_box_whp_engine/Cargo.toml:17-25) and decision 13 (`#[non_exhaustive]` error enums, rusty_box_whp/src/error.rs:9) are untouched.
- The injection spec's Stage 2 "TSC leaves the runtime path entirely (QEMU's `tsc_valid`): read once per stop/diagnostic, written only on restore under a partition time-suspend bracket" (spec:288-292) points the same way as host time.

**Measured claims verified against code:**
- Census doc (2026-08-29): "99.56 % ended on `Budget`", "Device latches ended zero slices", "hypervisor 4,150 ms of 105,989 ms = 3.9 %" (docs/perf/2026-08-29-whp-slice-census.md:29-38, 62-79) — consistent with `Yielded::Budget` being the countdown clamp (scheduler.rs:204-208 → engine.rs:1888-1897).
- Handoff: "77-82% of slice budgets convert to under the 3us routing threshold … Mean budget 18,587 ticks = 62us of guest time = 1.9us of host time after the 32x fast-forward" (docs/whp-alpine-handoff.md:151-153) — matches engine.rs:1207-1216 + :2911-2919 + :2961-2963. Its "slice sizing … tested to exhaustion" (:156-158) predates injection (memory note warns the same).
- Handoff "The one structural fact": "All six defects fixed this session were in that seam. None were in the emulator" (:92-105) — the seam is §4.
- Capabilities doc: "`CPUID` is answered in two places … the `Cpuid` exit … never fires (`exits: cpuid 0`)" (docs/whp-guest-capabilities.md:51-57) — consistent with `TRAPPED_CPUID_LEAVES` (engine.rs:70-103) being installed yet `burst_on_the_shadow` answering CPUID unfiltered; `CpuidResultList` (property 0x1004) noted as unused (:77-96; handoff:188-204).
- Memory-note claim "the 8042 has a continuous 150 µs serial-delay timer that caps every slice" — **VERIFIED** (§3): keyboard.rs:271 + timers.rs:211-222 + scheduler.rs:204-208; Bochs identical (keyboard.cc:123-125, config.cc:1102-1106).

## Assumptions of lockstep baked into the machine

Each entry: where the machine assumes the engine returns at the device deadline, or that ticks are earned per instruction — and what breaks under a vCPU that runs continuously.

1. `scheduler.rs:199-208` — the UP batch is `min(batch_size, curr_countdown)`; a continuous vCPU has no batch to clamp, and the countdown is never consulted.
2. `scheduler.rs:202-203, 281-286`; `engine.rs:33-38` — `strict`: "overshooting then is not a rounding error but a device firing late". Meaningless when devices fire on host time.
3. `run.rs:695-712` — a `Ticks` engine is handed the whole remaining budget "because `run_cpu_batch` already clamps a batch to the next device deadline". The clamp is the premise.
4. `run.rs:727-729`, `scheduler.rs:403-411`, `timers.rs:245-250` — the wheel advances ONLY by the batch's reported `Progress` at the boundary; while the engine holds the processor "the machine is not ticking" (engine.rs:1889-1896). Under a continuous vCPU nothing ever advances the wheel.
5. `run.rs:733-768`, `interactive.rs:355-420`, `scheduler.rs:130-170` — HLT fast-forward advances time only when the vCPU has halted AND returned; a VP parked inside `WHvRunVirtualProcessor` (XApic, probe finding 10) never reaches it.
6. `pc_system.rs:692-702, 718-786` — timers fire only inside `tickn`, whose production callers are `service_scheduler_boundary` (scheduler.rs:1164) and `isa_bus_delay`; `Yielded::Budget`'s own doc says a slice that ran on "would starve every timer in the machine" (engine.rs:975-983).
7. `timers.rs:375-380` → `scheduler.rs:864-887` → `engine.rs:1337/2181` — a LAPIC timer expiry becomes a vector only at a boundary and reaches the partition only at the next `stage_injection`; latency = slice end + boundary + head (the 158 µs median the injection spec measured, spec:19-21).
8. `scheduler.rs:1220-1288` (`sync_final_event_levels`), `io.rs:101-131` (`sync_io_events`) — IOAPIC deliveries and the PIC pin are published to the CPU event word at boundaries/exits; a device that raises a line while the vCPU runs is unseen until the vCPU exits for another reason or the alarm cancels it.
9. `engine.rs:2786`, `wiring.rs:31, 177-186` — the device clock inside a hardware slice is the wheel value at slice start; every timer armed by a device during the slice is anchored there ("an engine whose anchor EQUALS the wheel on every arm is one whose device clock does not advance within a slice"). A PIT/PM-timer/HPET read mid-slice returns a frozen counter while the guest's TSC runs at host rate.
10. `proc_ctrl.rs:317-331` (`system_ticks` LiveUp), `apic.rs:604-615` (`live_ticks`), `access.rs:247/295` — on the shadow, time advances one tick per shadow-retired instruction; TMCCT/RDTSC/HPET read through the shadow see almost no progress across a hardware run.
11. `apic.rs:2032-2055`, `proc_ctrl.rs:1289-1292` — TSC-deadline is armed as an absolute machine tick (Bochs apic.cc:1157-1159) though a hardware guest computed it from the host TSC; `pc_system.rs:1097-1102` clamps a "past" value to `now+1`.
12. `engine.rs:1786` — `set_tsc(state.msrs.tsc, wheel)` rebases the shadow TSC at every read-back: two TSC rates (host Hz vs ips·32) meet only at read-backs (divergence H2).
13. `engine.rs:2844-2856, 2982-2987, 1531` — guest time is earned two ways into one counter: `wall_in_run × ips × 32` for hardware, `1 per instruction` for shadow slices.
14. `engine.rs:1207-1216`, `alarm.rs:58, 165-229` — the 3 µs shadow-conversion floor and the 2 ms spin margin exist only because the machine must have the processor back at the deadline; both vanish when deadlines are not the engine's to honour.
15. `io.rs:274-277`, `cpu.rs:1871-1873` — `finish_the_instruction` and fast-REP stop when `get_num_cpu_ticks_left_next_event() == 0` (divergence D3).
16. `run.rs:783-797` — machine-side PIC injection keyed on `EVENT_DELIVERY == Machine`; `engine.rs:1113` sets `Engine`. A hypervisor LAPIC makes both arms obsolete for the LAPIC half.
17. `scheduler.rs:28-66` (`cpu_runnable_for_batch`), `run.rs:751-756`, `interactive.rs:394-396` — the scheduler reads `activity_state`/`interrupts_enabled()`/`lapic.intr` off the shadow between slices, assuming the slice-end read-back made it current.
18. `interactive.rs:117, 140-141` — the GUI asks in ≤100,000-instruction batches with `strict = true`; a `Ticks` engine under the GUI never sees `step()`'s "whole remaining budget" path.
19. `pc_system.rs:1455-1461`, `apic.rs:2457, 2627-2646` — timers and the LAPIC deadline are serialized as absolute ticks; host-time deadlines have no such value.
20. `scheduler.rs:232-262` — SMP rounds stamp each LAPIC's epoch per round from `pc_system.time_ticks()`; `SliceClock::FrozenRound` (cpu.rs:347-349) freezes time within a round.
21. `mod.rs:310, 340-400`; `timers.rs:148-164, 395-406` — the slowdown timer is the only place host time enters today (opt-in), via `thread::sleep` inside a timer callback.
22. `mod.rs:1500-1504`, `acpi.rs:787-790`, `pit.rs:1109-1114` — Bochs "clock: sync=realtime" survives as an opt-in realtime path for exactly two devices; the other clocks (HPET, RTC, VGA) have no such path.
